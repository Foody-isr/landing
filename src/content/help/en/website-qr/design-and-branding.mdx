Open Website, then Site design. Work in the draft and preview both desktop and mobile before publishing.

<span id="theme" />

## Choose a theme and colors

Select the theme, brand color and color style. Use custom background, text, muted, accent and divider colors where offered. Check text contrast on every background. A section override affects that section; site settings provide inherited defaults. The order mode screen inherits the site's default colors. You can assign a different shared color style to it under [the order page settings](/en/help/website-qr/order-page#service-before-menu). The bottom bar follows the site colors by default and has a pink animation accent. Open Mobile experience → Navigation → Bar colors to customize each part. See [Configure the mobile experience](/en/help/website-qr/navigation-and-footer#mobile-experience).

<span id="pink-coffee-template" />

## Preview the Pink Coffee template

Pink Coffee requires the compatible Website and Admin release. If it is not offered, ask Foody to confirm availability before changing the site. In Site design → Website themes, select Pink Coffee and Preview. Review the home page, order page, shared colors, fonts, navigation and existing content before choosing Apply theme. The template stages a short home page with a campaign hero and featured items, plus an order page; it does not create catalogue items, prices or payment settings. Replace the sample copy and media with your own, select the real items to feature and check the order-page menu association. Applying a template changes the draft only. Wait for saving, review desktop and mobile, then publish deliberately. See [sections and media](/en/help/website-qr/sections-and-media#campaign-hero). The compatible Pink Coffee presentation uses a staggered menu icon with no header cart icon, a manual carousel with controls on the right and a product grid that can span multiple rows. The counter and playback control are hidden in this manual preset; descriptions are shown while each card’s prices and buttons are hidden. Change these choices in the header, carousel and featured-item controls without changing catalogue prices.

<span id="display-headings" />

## Use a larger display heading

In a section’s title appearance controls, choose Display when the compatible release offers it. This size is intended for short presentation headings and adapts to mobile and desktop; it does not change the chosen font or text color. Keep the essential message outside images, check long titles and Hebrew direction, and compare both previews before publishing. Return to the previous size if the larger heading overwhelms the content.

<span id="fonts" />

## Set fonts and text roles

Open Website → Site design → Fonts. Under Headlines and Paragraphs, choose the family, Text size (%) and Text weight. Set size from 75% to 150% of the theme’s scale. Enter 100% to restore the original size and choose Automatic for the theme’s weight. The weight list follows the selected family. Desktop, mobile browser and installed app use the same values. Explicit section and order text styles take priority. Compare the desktop and phone previews, and check More and the bottom navigation in Installed app preview. Review long labels and Hebrew layout, then publish the draft.

If you enable a dedicated app home, check its carousel and featured product headings in [Mobile experience → App home](/en/help/website-qr/navigation-and-footer#app-home). They use the site typography.

<span id="images" />

## Frame item images

Choose fit, crop and focal point in the image controls. Compare the card and item detail preview on both screen sizes. Keep text outside image assets when it needs translation. Save the draft, then publish only after checking the public page.

<span id="mobile-fulfillment-review" />

## Review mobile order entry

When the invitation is enabled, on mobile and desktop, verify that Order without an account is immediately visible and usable, with Sign in as an option. No address field or confirmation should appear before choosing. Check opening/closing sign-in and guest access: address entry for Delivery, collection details without a delivery address for Pickup. Back must retain the draft; switching services or reopening the dialog must not repeat the guest choice. Also check a signed-in customer’s validated address card and Edit. In a 360 px visual viewport with at least four results, four whole 44 px suggestions must remain visible. The title, tabs, Back and input keep their positions when the keyboard opens or closes. Check 320 px screens, desktop and French, Hebrew and English. Sign in opens Google and the email/password form. Facebook and Apple appear only when configured by the service. Standalone email-code sign-in is no longer offered. Account creation, address verification and password-recovery codes remain separate. Check dismissal and resumption without losing the draft on mobile and desktop; four whole suggestions with the keyboard open retain the same geometry. Sign-in choices must not reintroduce moving tabs or input.

## Access the new controls

With the Order method format selected, customers go directly from their service choice to a separate pickup or delivery screen. The sign-in invitation applies on the Pickup and Delivery screens and in the classic window. On this flow, a compact order header uses the restaurant logo and colors. You can adjust its actions and the product presentation from the order page settings. The entry sign-in invitation is controlled in Website → Order page → Fulfillment → Show the sign-in invitation on arrival. Off goes directly to pickup/delivery details; when on, Order without an account remains immediately visible. Save the draft and publish to apply this choice. See [the journey setting](/en/help/website-qr/checkout-and-receipt#optional-entry-sign-in). When the invitation is off, a discreet Sign in link remains available on the Pickup and Delivery screens and in the classic window. It opens authentication only when selected; dismissing authentication retains entered details and allows ordering without an account.

## Set menu and category text colors separately

In Site design → Colors, select the style assigned to Item list, then open Customize menu colors → Category menu. Menu text controls the names and underline of menu tabs, such as BASSARI and HALAVI. Category text controls unselected group links, search and its icons. The selected group keeps its active text setting. The two colors are independent: changing or resetting one field to automatic does not change the other. Without a chosen menu color, tabs use the style’s paragraph color when readable against the bar, otherwise a suitable light or dark text color. Check both levels in preview, reload to confirm draft saving, then publish and review desktop and mobile. If the wrong color appears, check the style assigned to Item list; the Wolt preset uses its dedicated palette.
