Open Settings → WhatsApp. Select the supported connection/billing mode before entering credentials.

<span id="connection" />

## Connect a sender

Use Foody-managed connection or the restaurant’s personal Twilio account if offered. A personal sender must already be registered and online with approved Utility templates belonging to the same account. Enter secrets only in the protected form. A failed verification preserves the prior configuration; switching billing modes requires disconnecting first.

<span id="meta" />

## Use a gated Meta coexistence connection

Direct Meta coexistence is a controlled pilot and disabled by default. Connecting alone does not switch message routing; activate the intended provider explicitly after verification. The existing Business app remains available. Do not assume fallback to Twilio if a Meta send fails.

<span id="delivery" />

## Read message history

In the order’s communication panel inspect sent, delivered, read, failed and blocked-before-send records. A blocked automation is not proof of delivery. For a reviewed courier reminder use its explicit action only when eligible. Unknown provider outcomes are not automatically replayed; investigate before another send.

<span id="media-templates" />

## Create a model with a photo or PDF

In Settings → Communications → WhatsApp, a user with settings-edit permission can open Create a model. Choose the notification type, language and a new name, then Message attachment: Photo or PDF document. Upload a JPEG/PNG up to 5 MB for a photo, or a PDF up to 10 MB for a fixed document. For each order’s own receipt, choose PDF document then Document to send → Receipt for this order. The server uses a fictional sample document for Meta approval. Review the text and submit. Wait for Utility approval before assigning the model to a notification. An existing text-only model cannot gain an attachment afterward; create a new model with the required header type.

<span id="media-library" />

## Manage files and check sends

Files are available to authorized restaurant users through attachment configuration, without a public storage link. Preview file opens an authenticated preview. Delete file requires confirmation and refuses files referenced by a notification, saved stage or pending message. Replace the file in those settings and save first. The library allows 40 files and 100 MB per restaurant. If upload or deletion is unconfirmed, refresh the list before retrying. If transfer to Meta fails, Foody does not send the text alone or switch to Twilio. In the order → Customer messages, check the attachment filename recorded with the attempt and the status returned by WhatsApp; Read depends on WhatsApp’s return.

<span id="route-delivery-window" />

## Review a route-based delivery reminder

For an assigned delivery with a saved customer-window setting, reminders use the route arrival plus the configured duration, rather than the order’s broad scheduled slot. For example, arrival at 08:30 and 90 minutes produces 08:30–10:00. Configure it in Orders → Deliveries → allocation, beside the time at each stop, and review the manual or approved WhatsApp preview before sending. The same range supplies Twilio, Meta and stage reminders; existing template variables and J-1 eligibility remain in effect. Unconfigured historic routes keep the original saved slot. If the range cannot be verified, recalculate the route and reopen the reminder. A changed approved preview must be reviewed again before sending. Editing a template alone does not calculate a route or change its margin.
