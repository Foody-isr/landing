Admin → Settings → Order taking → Preorders

<span id="policy" />

## Choose the intake policy

Select whether preordering is disabled, offered alongside other orders, or required using the offered policy controls. Check enabled pickup/delivery services separately.

<span id="slots" />

## Configure date/time slots

Choose the slot calendar and set offered lead time, horizon and fulfillment windows. Test boundary dates in the preview rather than assuming all calendar dates are available.

<span id="batch" />

## Configure a batch cycle

Set ordering opening, cutoff and fulfillment days/windows for the cycle. Review pickup and delivery windows separately and inspect the generated cycle preview.

<span id="prepayment" />

## Check payment and product exceptions

Review the prepayment policy and product-specific exceptions. Save, reopen settings and test the published guest path without making a live payment as a test.

<span id="weekly-series-rollover" />

## Open the current weekly batch automatically

For a restaurant configured for weekly batches, open **Home** or **Orders** using the **Série** date basis. The current batch is selected by default even without orders; its totals then stay at zero. It advances after the previous batch’s final fulfillment day in the restaurant timezone, without waiting for the first order or for ordering to open. An open page follows this change on the next automatic refresh (about one minute) or when you return to the tab.

You can select an older service in the calendar; that selection stays in place while the page is open. An order for a later week does not replace the current batch as the default. A payment-attention link keeps its explicit period. If the date looks incorrect, check the configured fulfillment days and restaurant timezone, then reload. Rollover does not create an order or publish a menu.

<span id="manual-weekly-ordering" />

## Control weekly ordering manually

Weekly batch restaurants can choose Manual opening under Settings → Ordering & delivery → Orders & availability, with settings.edit. Save, then explicitly open or pause online orders using the pause control. Automatic opening/cutoff times do not control intake in this mode. Delivery days/windows, the restaurant timezone, preparation and stock rules remain in effect; existing orders are untouched. The website stays browsable during a pause. Active temporary test access must be disabled before reopening publicly. See the fulfillment settings guide for the complete procedure.
