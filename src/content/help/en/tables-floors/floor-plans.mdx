## Create a floor plan

Create a named floor plan, add the required tables and arrange their position, shape and capacity using the editor. Save before opening it on the POS.

<span id="sections" />

## Organize service sections

Review restaurant sections and table assignments. Keep table identities stable when rearranging a plan; moving a drawing is different from moving a financial check.

<span id="qr" />

## Prepare table QR cards

Open table QR settings, select the intended table and customize the available card style/text. Download or print the offered output and scan it to verify restaurant and table.

<span id="live" />

## Use the live table view

Select the correct floor plan on the POS and inspect table status before opening a check. An already open table resumes its current session without asking for covers again. Its usual Menu workspace shows the existing check and permitted actions; separated financial bills still require their own selection. Only a free table starting a new service requests covers according to the assigned mode. Reopening does not alter existing covers, seats, orders or payments. If the latest table/check read fails or its session changes, retry the read rather than opening a replacement service. Review covers/seats separately and confirm the saved check before payment or transfer. Selecting a table after changing a draft's fulfillment method is not a bill move or merge. A table with an existing financial check refuses and cancels that pending transfer, keeping the source draft intact; see [changing a draft's service](/en/help/orders/order-types#pos-change-draft). Several QR guests keep distinct order IDs and payments even when their food appears in the same table session.

If another POS starts service at the table while you are choosing covers, opening stops without replacing its covers or attaching your draft. Return to the floor plan, refresh, then reopen the table to review the current visit’s check. The previous draft stays in its original context: do not attach it to the next guests. If the state cannot be verified or an update is required, have the POS and server versions checked before trying again.

<span id="saved-layout-preservation" />

## Verify a saved layout after an update

After arranging tables, save the plan explicitly, reopen it in Admin and compare its positions, dimensions and rotations on the POS. The updated API preserves authored version-2 geometry during startup; only old formats are normalized. This correction prevents a restart from resizing a saved custom layout, but cannot reconstruct dimensions or angles already overwritten by an older version. If tables unexpectedly overlap, keep a screenshot and have the installed API version checked before saving another arrangement. Restore the intended drawing explicitly after the correction, or have an authorized operator review an available backup; do not assume an automatic restoration. Keep table identities and active checks intact: moving a drawing is not closing a service, transferring a bill or merging QR orders. Avoid saving from an old editor tab after another person has changed the plan.

<span id="service-time-and-state" />

## Track service duration and state

The duration on the floor plan and checks list starts with the table session, not the most recently added dish. Seating guests without entering covers also starts service; an open table is not free merely because its cover count is absent. Reopening the check, sending another batch or receiving a QR order in the same session does not restart the duration. QR guests retain separate orders and payments. Scanning a QR alone does not prove occupancy. Pickup and delivery orders must not occupy a table. Kitchen, payment and checkout-request states remain distinct from this duration. After confirmed closure, cached orders must not revive the old service; a new occupation has its own session. If a read fails, refresh and verify server state before closing or reseating the table.

A financial summary does not prove that food is in the kitchen: review the check’s recorded progress. Unknown preparation does not reset the table timer or confirm that the table was released.

<span id="mobile-terminal" />

## Use Checks on mobile

On the updated terminal, the bottom receipt icon opens Checks. Tap the view selector to choose All checks or a floor plan in the same radio sheet. All checks combines accessible named checks and open tables; choosing a floor returns to its tables. Search opens the searchable check list. Restaurant positions, shapes and states remain authoritative; drag the plan to reach off-screen tables without editing its geometry. Open a free table and, if prompted, choose the guest count or No covers; Back cancels the choice. The + button offers authorized sales and tools, including Actions for staff filters, To do and Refresh. Permissions and settings continue to limit destinations. Neither an offering nor an animation releases a real table without server confirmation. The sheet also reserves space above Android system buttons so its last option remains visible and reachable. Scroll the list when all floors do not fit the available height.
