Open Staff → Table service to assign access. Table status and assistance are configured under Settings.

<span id="assign" />

## Assign rooms, sections and tables

Choose free, collaborative or strict assignment mode, read its displayed access rule, then modify an eligible staff member’s assignment. Select rooms, sections or specific tables and review the resulting covered-table count. Staff with unrestricted table access remain explicitly identified.

<span id="status" />

## Maintain table state

Review the available status labels and table/session controls. An occupied table can have multiple bills: check the active session and covers before seating, moving or closing. Changing a visual status is not proof that a bill was paid. Changing an unsent draft's fulfillment method does not move or merge an existing bill or replace its lifecycle. Choosing a table with a financial check cancels the pending draft transfer and leaves the source intact; follow [the draft-service procedure](/en/help/orders/order-types#pos-change-draft).

<span id="resume-confirmed-table-service" />

## Resume the correct table service

On a compatible updated POS, opening an occupied table resumes only its confirmed current session without restarting its service or asking for its covers again. Its timer is not reset. Configured cover prompts still apply when starting a new occupancy. If the table closes or changes session while loading or transferring a draft, navigation into the old context stops. Return to the floor plan and reopen the current table; do not force food onto the next party’s service. Verify an unconfirmed transfer before sending an order again. Older outstanding orders remain separate and viewable by number in [Orders](/en/help/settings/pos-workspace#previous-table-service-orders). Opening the table neither settles nor closes those older orders.

<span id="timer-settings-and-close" />

## Verify table thresholds and closure

In table-status settings, review indicators, the in-service color and yellow/red thresholds in minutes, then save. These are restaurant-wide settings: changing POS mode does not create separate thresholds. If the server does not confirm changed fields, the draft remains with a save error; reload or correct it before relying on the new colors. A color change neither collects money nor closes a table. Closure refuses outstanding orders; a fully refunded order is no longer an active debt. The table and its QR sessions close together or remain unchanged on failure. If service changed while creating an order, reopen the table instead of forcing the old context. This does not perform terminal deposit or bank settlement.

<span id="assistance" />

## Configure assistance requests

In Table assistance enable the supported requests and staff notifications appropriate to service. Check the assigned staff/device recipients. On the service screen acknowledge or resolve the request after attending the guest; an assistance request does not create a payment.

<span id="mobile-terminal" />

## Find service tools on mobile

In Checks on the updated terminal, the radio selector connects All checks with available floor plans. Open + then Actions for the staff filter, To do and Refresh. Assignment restrictions and permissions still limit accessible tables and checks. The plan can pan on screen; neither panning nor switching views saves new geometry, assigns staff or releases a table. The active user’s name supplies the initials at the lower left; that button opens More without changing service assignment.
