## Inspect the last terminal transaction

With a compatible version and permission to manage payments, open More → Settings → Hardware → Payment terminals. Open the details of the intended terminal, choose Last terminal transaction, then press Read last transaction. On iPad, FoodyPOS can connect to that verified terminal when it is reachable on the local network. For a Portable listed in inventory only, open its details in FoodyPOS on the Portable itself. Opening the dialog sends no query. If the connection fails or the identity cannot be confirmed, use Test connection on the same screen and verify the pairing. The payment default stays as configured. Inspection shows only the reference, type, reported result and amount when available. A preauthorization stays distinct from a purchase; no payment or check is changed. When the response includes a card receipt, expand Customer copy or Merchant copy to see its printable fields and the masked card number. An empty response, including after restart, does not prove that no payment occurred. For a pending payment or deposit, return to its original verification flow: inspection clears no lock and replays no operation. After changing account, restaurant, permission or terminal, read again; the old result is not reused. If the terminal fields are incomplete, Foody reads available details from the Ashrait receipt with the same reference. Missing or conflicting information stays Unconfirmed. Compare the reference with the sale in Transactions. Do not retry a payment based on this view alone.

When Foody has a pending card payment, a manager can inspect the original terminal if it is connected, identified and ready. The screen shows that terminal’s latest known transaction. Have the original attempt verified if the result is empty or concerns a different sale. Once the attempt is resolved, available copies can be requested.

## Israeli Ashrait report capabilities

In the compatible Israeli Ashrait version, the old generic View current totals, Close only and Transmit only actions are removed. For end of day, use Current drawer and its explicit terminal transmission. Sales recorded by Foody are not the terminal’s bank totals. If Ashrait confirms a deposit without numeric results or a batch reference, those details remain unavailable; they are not zero. Other commands described in provider documentation are not necessarily available in Foody. Have a manager and Verifone confirm availability and the procedure before advanced financial or maintenance operations.

## Recover an interrupted Ashrait payment

If the terminal response is lost, open the check on the original register with the same terminal connected. Choose Pay, Card, then Review the card payment. This checks the existing attempt without starting another debit. You can start again if Foody confirms the attempt stopped before collection, was declined, or was cancelled. A matching authorization is recorded against the original check. If the terminal returns an empty or different result, give the displayed reference to a manager to check the Verifone journal. The result needs confirmation before taking another payment on this check. A separate register with a different terminal can collect a different check.

## Print the terminal card receipt

In Last terminal transaction, choose View last transaction, then expand Customer copy or Merchant copy if available. The details include the printable fields Ashrait returned for that copy. Select the corresponding card receipt print action. On the Portable it prints on the integrated printer. On the iPad it uses the configured Epson receipt printer. After a confirmed print, use Print another copy if requested. When paper status is uncertain, check the printer before attempting a new copy. For an earlier recorded payment or refund, open its card receipt in Transactions.
