Connexion Admin et menu du compte

<span id="activate" />

## Activer une invitation

Ouvrez l’invitation reçue par e-mail, vérifiez le restaurant, choisissez votre mot de passe et confirmez vos coordonnées. Le code caisse est demandé uniquement si les permissions affectées dans ce restaurant permettent la prise de commande (orders.manage) ou la gestion des paiements (payments.manage). Un livreur avec les droits habituels de consultation, ou un rôle limité à la cuisine, termine sans cette étape. Le nom du rôle ne détermine pas à lui seul cette obligation. Ne partagez jamais de mot de passe ni de code caisse.

<span id="restaurant" />

## Sélectionner le restaurant

Connectez-vous avec votre compte puis choisissez un restaurant autorisé. Vérifiez son nom avant toute modification ou export.

<span id="recover" />

## Récupérer l’accès

Après un refus de code caisse ou un échec d’enregistrement, rouvrez le même lien e-mail encore valide et réessayez ; une activation échouée ne le consomme pas. Un code déjà utilisé impose à l’utilisateur de la caisse de choisir un autre code de 4 à 6 chiffres. Un livreur sans droits caisse n’a pas à essayer d’autres combinaisons. Si le lien a expiré, ne permet pas d’identifier le restaurant ou indique avoir déjà été utilisé alors que l’activation n’a pas abouti, demandez à un responsable autorisé d’ouvrir Personnel → Employés → le membre → Renvoyer l’invitation de configuration. Utilisez le dernier e-mail reçu ; le renvoi invalide les anciens liens inutilisés sans recréer le membre. Si l’activation a déjà réussi, connectez-vous avec le mot de passe choisi ou utilisez la récupération de mot de passe. Un accès retiré doit être vérifié par le responsable. Ne partagez jamais de lien d’activation ni d’identifiants avec l’assistant.

<span id="terminal-pin-sign-in" />

## Entrer en service sur le terminal

Sur un POS déjà enrôlé, l’écran Se connecter affiche Saisissez votre code confidentiel. Saisissez votre code personnel complet de 4 à 6 chiffres, puis touchez Démarrer le shift. Les quatre emplacements affichés au départ s’étendent quand vous entrez un cinquième chiffre ; ils ne limitent pas un code existant à quatre chiffres. La touche de correction efface le dernier chiffre. L’entrée n’est pas validée automatiquement : attendez le résultat de la connexion avant d’utiliser le POS. Un refus affiche une erreur et vide la saisie pour réessayer ; ne partagez jamais votre code. Configurer ce terminal avec email et mot de passe permet de revenir au formulaire de connexion. Une session PIN réussie ouvre aussi votre service ; le rôle et les droits restent ceux de votre compte. Afficher les heures ouvre un parcours distinct : consulter son statut n’ouvre ni service ni session de vente. Voir [l’enregistrement des heures](/fr/help/staff/devices-and-shifts#personal-time-tracking).

<span id="end-pos-shift" />

## Terminer un shift de caisse en sécurité

Sur un POS autorisé, utilisez Se déconnecter dans la navigation ou Terminer le shift dans Plus. Si ce POS a une caisse ouverte ou une opération espèces en attente, Rapport de tiroir-caisse en attente apparaît avant la fin du shift. Annuler conserve votre connexion ; Terminer le rapport ouvre Solde en caisse sans clôture ni déconnexion. Résolvez l’opération en attente, comptez physiquement et clôturez la caisse sur le même POS, puis redemandez la déconnexion et confirmez Terminer le shift. Sans droits sur le rapport, demandez à un responsable autorisé. Si le statut de caisse est invérifiable, la session reste ouverte : vérifiez la connexion et réessayez. Le dépôt Verifone est distinct et ne démarre jamais automatiquement. La fin du shift conserve l’autorisation de cet appareil pour la prochaine connexion PIN. Voir [la procédure du rapport en attente](/fr/help/staff/devices-and-shifts#pending-cash-sign-out).

Si la réponse à Terminer le shift est incertaine, [vérifiez la fin avec Réessayer](/fr/help/staff/devices-and-shifts#uncertain-shift-end). Ne recréez pas une fin de période et ne supprimez pas les données pour contourner un statut non confirmé.
