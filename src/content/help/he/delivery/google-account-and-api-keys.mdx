הכינו פרויקט Google Cloud בבעלות העסק. בשלב הראשון פנו ל-Foody לתיאום חיבור ידני לפני העברת פרטי גישה טכניים.

## זמינות וגישה

**לפני שמתחילים:** הבעלים או מנהל מורשה צריכים לשמור שליטה בחשבון, בחיוב ובמפתחות. הכינו כתובת דוא״ל עסקית נגישה, אמצעי תשלום ש-Google מקבלת והרשאה להתחייב להוצאות העסק.

**הזמינות הנוכחית ב-Foody:** המסך **הגדרות → משלוח → מפות** מציג ספק ונתוני שימוש; אין בו טופס להזנת מפתחות בבעלות העסק. Foody צריכה לאשר חיבור אישי. המדריך מאפשר להכין בקשה; הוא אינו מבטיח הפעלה או סיום שימוש משותף. המתינו לאישור טיפול לפני הפעלת שירותים בתשלום או יצירת קובץ סודי.

המטרה היא לשייך את קריאות העסק לפרויקט שלו, עם מעקב וחיוב Google משלו. אין צורך בחשבון נפרד לכל עובד או לקוח קצה. למספר סניפים יש לתאם עם Foody את היקף החיבור והפרויקטים.

<span id="account" />

## 1. יצירה או בחירה של חשבון Google לעסק

1. פתחו את [יצירת חשבון Google](https://accounts.google.com/signup), או היכנסו לחשבון העסקי הקיים ועברו ישירות לאבטחתו.
2. לחשבון חדש מלאו את הפרטים ש-Google מבקשת: שם פרטי, שם משפחה ופרטים כלליים.
3. בחרו כתובת Gmail או באפשרות לשימוש בכתובת הדוא״ל הקיימת שלכם. אין חובה להשתמש ב-Gmail.
4. אם Google שולחת קוד אימות לדוא״ל, הזינו אותו במסך של Google. צרו סיסמה ייחודית והשלימו את הבדיקות המוצגות.
5. פתחו [אבטחת החשבון](https://myaccount.google.com/security), ואז **2-Step Verification / אימות דו-שלבי**, והשלימו את ההגדרה. הוסיפו גם כתובת דוא״ל וטלפון לשחזור שבשליטתכם.

**תוצאה:** הגישה לחשבון נשארת בידי העסק. לעולם אל תעבירו ל-Foody סיסמה או קודי כניסה. [עזרה של Google בנושא חשבונות](https://support.google.com/accounts/answer/27441?hl=he).

<span id="project" />

## 2. יצירת פרויקט Google Cloud ייעודי

1. פתחו את [Google Cloud Console](https://console.cloud.google.com/) ואשרו תנאים אם Google מציגה אותם.
2. לחצו על בורר הפרויקט בחלק העליון ואז על **New project / פרויקט חדש**.
3. בחרו שם ברור, לדוגמה **Foody Example Restaurant**. אם מוצע ארגון עסקי, בחרו בארגון שלכם.
4. לחצו על **Create / יצירה** ובחרו את הפרויקט.
5. העתיקו את **Project ID / מזהה הפרויקט**, לדוגמה `foody-example-restaurant`, ושמרו גם את מספר הפרויקט. השם המוצג והמזהה הם פרטים שונים.

**תוצאה:** פרויקט ייעודי לשימוש שלכם ב-Foody, נפרד מפרויקטים של עסקים אחרים. [מדריך Google ליצירת פרויקט](https://docs.cloud.google.com/resource-manager/docs/creating-managing-projects).

<span id="billing" />

## 3. שיוך חשבון החיוב של העסק

בצעו שלב זה לאחר ש-Foody אישרה את הטיפול בחיבור.

1. פתחו **Billing / חיוב** במסוף.
2. צרו חשבון חיוב או בחרו בחשבון העסקי הקיים.
3. בדקו מדינה, מטבע, פרטי עסק ואמצעי תשלום ישירות מול Google.
4. שייכו אליו את הפרויקט החדש וודאו שהחיוב פעיל.

**תוצאה:** השימוש שמיוחס לפרויקט יחויב על ידי Google בחשבון המשויך. יצירת חשבון Google אינה הופכת את שירותי ה-API לחינמיים. תעריפים וספי שימוש חינמיים, אם קיימים, תלויים בשירות ובתנאי Google; אין הבטחה לשימוש חינם לצמיתות. [עזרה של Google בנושא חיוב](https://docs.cloud.google.com/billing/docs/how-to/create-billing-account).

<span id="services" />

## 4. הפעלת שירותי API שאושרו על ידי Foody בלבד

בפרויקט הנכון פתחו [APIs & Services → Library / ממשקי API ושירותים → ספרייה](https://console.cloud.google.com/apis/library). חפשו כל API שאושר, פתחו את העמוד שלו ולחצו **Enable / הפעלה**.

| הצורך ב-Foody | שירות Google לחיפוש | ההגדרה הנדרשת |
| --- | --- | --- |
| הצעות כתובת ופרטי הכתובת שנבחרה | **Places API (New)** | מפתח שרת לחיפוש כתובות |
| המרת כתובת לקואורדינטות | **Geocoding API** | מפתח שרת למשלוחים |
| תוואי דרך, מרחקים וזמני נסיעה | **Routes API** | מפתח שרת למשלוחים |
| מפת Google ברקע של תצוגות משלוח | **Map Tiles API** | מפתח שרת למשלוחים |
| מיטוב עצירות ושיבוץ שליחים | **Route Optimization API** | אימות שרת עם חשבון שירות; מפתח API לבדו אינו מספיק |

הזמינות בפועל תלויה בגרסת Foody ובהגדרות שלכם. בפרויקט חדש השתמשו ב-**Places API (New)** וב-**Routes API**; אל תפעלו לפי מדריך ישן שדורש כברירת מחדל Directions, Distance Matrix או Places Legacy. [הגדרת Google Maps](https://developers.google.com/maps/get-started), [הגדרת Places](https://developers.google.com/maps/documentation/places/web-service/get-api-key) ו[שירותי Legacy](https://developers.google.com/maps/legacy).

<span id="keys" />

## 5. יצירה והגבלה של מפתחות API לשרת

1. פתחו [APIs & Services → Credentials / פרטי כניסה](https://console.cloud.google.com/apis/credentials).
2. לחצו **Create credentials → API key / יצירת פרטי כניסה → מפתח API**.
3. תנו למפתח הראשון את השם **Foody – Server addresses**. תחת **API restrictions**, בחרו **Restrict key** ורק את **Places API (New)**.
4. צרו מפתח שני בשם **Foody – Server delivery**, והגבילו אותו לשירותי המשלוחים שאושרו בשלב 4: **Geocoding API**, **Routes API** ו-**Map Tiles API**, לפי הצורך.
5. לכל מפתח, תחת **Application restrictions**, בחרו **IP addresses** והזינו רק כתובות IP קבועות ליציאה שנמסרו על ידי Foody. שמרו.

**אם Foody עדיין לא אישרה כתובות IP ליציאה, עצרו לפני שימוש במפתח.** אל תנחשו כתובת, אל תשתמשו בכתובת הקופה או הנתב ואל תסירו הגבלות כדי לאפשר בדיקה. אם האירוח דורש שיטה אחרת, Foody צריכה לאשר אותה.

מפתח שרת הוא סודי. אין צורך ליצור לצדו ״client secret״. [הגבלת מפתחות Google](https://support.google.com/googleapi/answer/6310037?hl=he).

<span id="browser" />

## 6. יצירת מפתח דפדפן רק אם Foody מבקשת

תהליך השרת שתואר אינו דורש מפתח ציבורי. אם Foody מאשרת שהגרסה שלכם פונה ל-Google ישירות מהדפדפן:

1. צרו מפתח **נפרד** בשם **Foody – Web**.
2. תחת הגבלות יישום בחרו **Websites / אתרים** והוסיפו את הדומיינים ודפוסי ההפניה המדויקים שמסרה Foody, כולל הדומיין האישי שלכם אם נדרש.
3. הגבילו את השירותים לאלה שנדרשו במפורש לתהליך, לדוגמה **Maps JavaScript API** וגרסת Places שנבדקה כתואמת.

לעולם אל תשתמשו במפתח השרת. אל תאפשרו את כל האתרים או דומיינים כלליים של תצוגה מקדימה. אם גרסה ישנה דורשת Places Legacy בפרויקט חדש, פנו ל-Foody לבדיקת תאימות. מפתח דפדפן עשוי להיות גלוי בעמוד; ההגבלות הכרחיות. [כללי האבטחה של Google Maps](https://developers.google.com/maps/api-security-best-practices).

<span id="service-account" />

## 7. הכנת אימות למיטוב מסלולים, אם נדרש

**רק אם Foody מאשרת מיטוב באמצעות Google עבור העסק שלכם.** [Route Optimization משתמש ב-OAuth בצד השרת](https://developers.google.com/maps/documentation/route-optimization/cloud-setup), ולא בסוד התחברות של לקוח.

1. באותו פרויקט פתחו [IAM & Admin → Service Accounts / חשבונות שירות](https://console.cloud.google.com/iam-admin/serviceaccounts).
2. לחצו **Create service account**, בחרו בשם `foody-delivery` והמשיכו. [יצירת חשבון שירות](https://docs.cloud.google.com/iam/docs/service-accounts-create).
3. העניקו לחשבון בפרויקט את התפקיד **Route Optimization Editor** (`roles/routeoptimization.editor`). אל תעניקו את התפקידים הכלליים Owner או Editor. [התפקיד הנדרש למיטוב](https://docs.cloud.google.com/iam/docs/roles-permissions/routeoptimization).
4. מסרו ל-Foody את כתובת הדוא״ל של חשבון השירות ואת מזהה הפרויקט, ללא מפתח פרטי. תחילה אשרו את שיטת האימות וההעברה המאובטחת.
5. **רק אם Foody מבקשת קובץ JSON:** פתחו את החשבון → **Keys → Add key → Create new key → JSON → Create**. שמרו את הקובץ שהורד במקום מוגן והעבירו אותו רק בערוץ המאובטח שסוכם. אם הארגון אוסר יצירת מפתחות, בקשו שיטה מאושרת ואל תעקפו את המדיניות. [ניהול מפתחות חשבונות שירות](https://docs.cloud.google.com/iam/docs/keys-create-delete).

קובץ JSON זה מכיל מפתח פרטי: לעולם אל תדביקו אותו בצ׳אט, בדוא״ל רגיל, במאגר קוד או בצילום מסך.

<span id="costs" />

## 8. הגדרת התראות ומכסות לפני בדיקה

1. פתחו **Billing → Budgets & alerts / חיוב → תקציבים והתראות**. צרו תקציב לפרויקט ובחרו נמענים.
2. הגדירו סכום שמתאים לעסק והתראות, לדוגמה ב-50%, 80% ו-100%.
3. תחת **Google Maps Platform → Quotas**, בחרו כל API שבשימוש ותאמו עם Foody את המגבלות הזמינות.
4. בדקו דוחות Google לפי פרויקט ושירות, במיוחד אחרי הבדיקות הראשונות.

**התראת תקציב אינה עוצרת הוצאות.** מכסות מגבילות יחידות שימוש בהתאם ל-API ואינן מבטיחות תקרת חיוב כספית מדויקת. מכסה נמוכה יכולה להשבית כתובות או מסלולים. מגבלות והצעות Foody נשארות נפרדות. [שליטה בעלויות Google Maps](https://developers.google.com/maps/billing-and-pricing/manage-costs).

<span id="handoff" />

## 9. העברת פרטי ההגדרה ל-Foody בשני שלבים

**תחילה פנו ל-Foody ללא סודות.** השתמשו ב[יצירת קשר עם Foody](/he/contact) או באיש הקשר הרגיל כדי לבקש טיפול וערוץ העברה מאובטח. טופס יצירת הקשר ועוזר מרכז העזרה אינם מיועדים להעלאת פרטי גישה.

אפשר להכין הודעה כזו:

> ברצוני להשתמש בפרויקט Google משלי עבור העסק. שם העסק ומזהה Foody: להשלמה. מזהה פרויקט Google: להשלמה. שירותים מבוקשים: כתובות / מפות / מסלולים / מיטוב. חיוב פעיל: כן או לא. איש קשר אחראי: להשלמה. נא לאשר תאימות, הגבלות וערוץ מאובטח להעברת פרטי הגישה.

**בהמשך, רק לאחר אישור הערוץ וההיקף:** העבירו את מפתח השרת לכתובות, מפתח השרת למשלוחים, ורק אם נדרשו גם מפתח דפדפן וקובץ JSON של חשבון שירות. ציינו את ייעודו של כל מפתח, ההגבלות שהוגדרו והסניפים הרלוונטיים. Foody צריכה לאשר את השיוך לעסק לפני כל בדיקה בתשלום.

לעולם אל תעבירו סיסמת Google, קודי אימות או שחזור, פרטי בנק, אסימונים זמניים או ״client secret״ להתחברות OAuth. אל תכניסו מפתחות להערות הזמנה, להגדרות אתר ציבוריות או לצ׳אט של מרכז העזרה.

## 10. בדיקת ההפעלה והשימוש בפרויקט שלכם

יצירת מפתחות או בחירה ב-Google ב-Foody אינן משנות לבדן את החיוב. המתינו לאישור כתוב מ-Foody שמפרט אילו שירותים וסניפים חוברו בפועל. אם החיבור האישי עדיין אינו זמין, השאירו את הבקשה בשלב הכנה.

לאחר אישור ההפעלה תאמו בדיקה קטנה שעשויה לצרוך מכסת Google:

1. בדקו חיפוש כתובת ציבורית ללא נתוני לקוחות.
2. בדקו מפת רקע ומסלול קצר; בדקו מיטוב רק אם הוא נכלל בחיבור.
3. ב-Google Cloud ודאו שהקריאות מופיעות ב**פרויקט שלכם**, לפי API ומפתח כשמידע זה זמין. ייתכן עיכוב בדוחות.
4. בקשו מ-Foody לוודא שהקריאות האלה כבר אינן משתמשות בפרטי הגישה המשותפים ושהן מוגבלות לעסק שלכם. המונים ב-Foody לבדם אינם מוכיחים איזה פרויקט מחויב.

**תוצאה צפויה:** השירותים שאושרו משתמשים בפרויקט שלכם, עם ההגבלות, המכסות והחיוב שלו. [בדיקת ספקים ושימוש ב-Foody](/he/help/delivery/maps-and-usage). במצב השליח בחרו מסלול למעלה: המפה וציר העצירות מוצגים יחד. בחרו סמן להצגת העצירה שלו; הצפייה אינה משנה סדר או מצב. הגדרות המסלול נמצאות בהתאמה והניווט בסרגל הקבוע. אם החלפת ספק מסתירה נקודת Google, בדקו את הספק הפעיל לפני תיקון הכתובת.

<span id="other-google-services" />

## 11. הבנת שירותי Google נוספים והחלפת מפתח

**כניסה באמצעות Google:** היא משתמשת בהגדרות זהות נפרדות. אין ליצור לקוח OAuth או סוד התחברות עבור מדריך זה.

**קריאת מסמכים:** Foody יכולה להשתמש ב-Google Cloud Vision לזיהוי טקסט בתעודות משלוח כאשר השירות מוגדר. מסך המפות אינו מציע חיבור Vision נפרד לכל עסק; אל תפעילו **Cloud Vision API** ואל תעבירו מפתח נוסף ללא בקשה ואישור ייעודיים מ-Foody. Google Pay אינו מוגדר באמצעות מפתחות המיפוי האלה.

**החלפה מתוכננת:** צרו מפתח חדש עם אותן הגבלות, העבירו אותו באופן מאובטח, המתינו לאישור החלפה ובדקו לפני מחיקת הישן. תאמו באותו אופן גם החלפת מפתח של חשבון שירות.

**מפתח שנחשף או שימוש חשוד:** פנו מיד ל-Foody ובטלו את המפתח שנחשף ב-Google Cloud ללא המתנה להחלפה מתוכננת; הדבר עלול להפסיק את השירות. בדקו קריאות והוצאות בפרויקט שלכם.
